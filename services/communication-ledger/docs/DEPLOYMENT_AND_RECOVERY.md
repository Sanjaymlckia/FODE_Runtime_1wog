# Staging deployment, backup, restore, and future Apps Script client

Do not deploy until independent HTTPS and hostname coverage for `ledger-staging.kiafode.com` are proven. Upload only the archive from `php scripts/package-deployment.php` into `/home/kundghlt/ledger-staging.kiafode.com`; preserve the protected external config file and do not upload `config.php`, logs, backups, tests, Git metadata, or build artifacts. Inspect `manifest.json` hashes before upload. Run migrations only after an authorized staging release CIS.

Backup and restore tools are deliberately operator-gated. Backups must use protected configuration, generate a checksum, apply governed retention, and never expose a password in shell arguments or history. Restore verification is separately targeted: validate checksum, restore to a verification database only, compare schema/table/row counts, validate foreign/unique constraints, then conduct a signed service write/read proof. Never overwrite the staging database.

Apps Script will use `LEDGER_API_BASE_URL`, `LEDGER_API_KEY_ID`, `LEDGER_API_SIGNING_SECRET`, and `LEDGER_ENVIRONMENT`. It serializes canonical JSON, SHA-256 hashes exact UTF-8 bytes, generates cryptographically random single-use nonces, timestamps UTC, signs the six-field canonical request, and uses a short timeout. It may retry transport failures only before provider authority; a timeout or lost response after authority is `SEND_UNCERTAIN` and must query durable operation state—not resend. Future methods: health check, preview create, operation resolve, receipt/event append, cohort create, and cohort resume.
